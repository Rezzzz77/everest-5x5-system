# نکات امنیتی — سیستم ۵×۵ تیم اورست

## وضعیت فعلی (MVP)

اپ در حالت **یلو** است: کلید `anon` عمومی در کلاینت است و سیاست RLS به هر کسی که کلید را داشته باشد اجازه خواندن/نوشتن می‌دهد.

| ریسک | شدت | توضیح |
|------|-----|-------|
| خواندن داده دیگران | متوسط | با `user_id` هر شخصی می‌توان `state_data` او را خواند |
| نوشتن روی داده دیگران | متوسط | همین جدول بدون بررسی مالکیت قابل overwrite است |
| نشت `anon key` | کم | این کلید برای استفاده عمومی طراحی شده؛ ریسک اصلی RLS سست است |

## مسیر ارتقا (قبل از استفاده واقعی)

1. **فعال‌سازی Supabase Auth** (Magic Link یا OTP موبایل).
2. تغییر سیاست RLS به:
   ```sql
   create policy "users own their row"
     on public.user_state
     for all
     to authenticated
     using (auth.uid()::text = user_id)
     with check (auth.uid()::text = user_id);
   ```
3. حذف سیاست `anon` قبلی.
4. افزودن ستون `owner uuid references auth.users(id)` و مهاجرت داده‌های موجود.

## هرگز انجام نده

- ❌ قرار دادن `service_role key` در کد کلاینت
- ❌ کامیت کردن `.env` یا فایل حاوی کلیدها
