## ۲. مدل کسب‌وکار در یک نگاه

سیستم پنج‌مرحله‌ای رشد تیم فروش:

1. **شروع (۷۲ ساعت)** — هدف، داستان، لیست ۳۰ نفره، ۲۰ دعوت، اولین ارائه
2. **حرکت (۷ روز)** — ۵ عادت روزانه + زنجیره ۷ روزه + گزارش شبانه
3. **ساخت (۳۰ روز)** — دانش محصول، آدم‌یابی، لیست ۱۰۰+، دعوت، پیگیری
4. **تکثیر (۹۰ روز)** — چرخه ۵ گامی: یاد بگیر → انجام بده → نشان بده → همراهی کن → واگذار کن
5. **راهبری (مستمر)** — داشبورد KPI، جلسات هدفمند، ۵ استاندارد راهبر

مرحله بعدی فقط با تکمیل «معیار عبور» مرحله قبل باز می‌شود (`getHighestUnlockedStage`).

## ۴. تصمیم‌های ثبت‌شده (ADR سبک)

### D1 — Offline-first، نه Cloud-first
اپ باید بدون اینترنت کامل کار کند (کاربران میدانی فروش).
→ `localStorage` منبع حقیقت محلی؛ Supabase فقط آینه (mirror).
→ اگر Supabase تنظیم نشده باشد، اپ باید **بی‌صدا** آفلاین کار کند.

### D2 — Supabase بدون Auth در MVP
برای رسیدن سریع به نسخه قابل استفاده، `anon key` + RLS سهل‌گیرانه.
⚠️ **بدهی فنی شناخته‌شده** — جزئیات در `docs/SECURITY.md`.
هیچ داده حساس (کد ملی، شماره تماس) نباید تا فعال‌سازی Auth به‌صورت عمومی بماند.

### D3 — تفکیک ماژول‌ها
`app.js` = رفتار · `src/db.js` = داده · `src/defaults.js` = محتوا · `src/config.js` = کلیدها.
محتوا (مراحل، ویژگی‌ها، محصولات) باید بدون دست‌زدن به منطق قابل ویرایش باشد.

### D5 — کلیدهای Supabase در `localStorage`، نه در کد
ادمین باید بتواند بدون build/کامیت وصل شود → مودال ☁️ + `saveSupabaseConfig`.
`getSupabaseConfig()` اول `localStorage` را می‌خواند، بعد `src/config.js`.
هیچ کلیدی در گیت نیست؛ پس ریپوی عمومی امن می‌ماند.

### D4 — گراف دانش به‌عنوان ابزار توسعه
`tools/build_graph.py` گراف را از منبع تولید می‌کند (نه دستی).
بعد از هر تغییر ساختاری باید دوباره اجرا و کامیت شود.

## ۵. باگ‌هایی که حل شد (تکرار نکن)

| # | مشکل | ریشه | راه‌حل |
|---|------|------|--------|
| B1 | هیچ دکمه‌ای کار نمی‌کرد | `onclick` در HTML به توابع global نیاز دارد، اما `app.js` یک ES Module است و توابعش global نیستند | `Object.assign(window, {...})` در انتهای `app.js` |
| B2 | پس از رفرش، لیست‌ها خالی می‌شد | `loadFromStorage()` داده ناقص/قدیمی را بدون ادغام برمی‌گرداند | `mergeWithDefaults()` کلیدهای گم‌شده را با پیش‌فرض پر می‌کند |
| B3 | ذخیره ابری رکورد تکراری می‌ساخت | درج ساده بدون کلید یکتا | `POST ...?on_conflict=user_id` + هدر `resolution=merge-duplicates` |
| B4 | نسخه قبلی روی هر تغییر، دیتای دمو را برمی‌گرداند | دمو به‌جای `defaults` در داده اصلی بود | `defaults.js` = خالی؛ `DEMO_DATA` جدا و فقط برای نمایش |
| B5 | لینک `manifest` و آیکون‌ها گم شده بودند | بازنویسی ویرایشی head | لینک‌ها بازگردانده شد + آیکون PNG واقعی ساخته شد |
| B6 | خطر تکرار B1 در آینده | هیچ تستی قرارداد HTML↔JS را نمی‌سنجید | `tools/check_contracts.py` + اجرا در CI |
| B7 | URL با اسلش انتهایی «پیکربندی ناقص» می‌داد | `isConfigured` نرمال‌سازی نمی‌کرد | `normalizeConfig()` در config.js + استفاده در db.js (تست واحد دارد) |
| B8 | CI به‌خاطر timestamp گراف همیشه قرمز بود | فیلد `generated` غیرقطعی | حذف فیلد، `schema:1`، خروجی بایت‌به‌بایت قطعی |
| B9 | کاربران قبلی نسخه قدیمی اپ را می‌دیدند | استراتژی cache-first + ثابت‌بودن نام کش | با هر انتشار مهم، `CACHE` در `sw.js` را bump کن (الان v3) |

## ۷. نکات محیطی (Termux)

- `file://` کار نمی‌کند (ES Modules + CORS) → باید `python3 -m http.server` اجرا شود.
- GitHub Pages از `main` ریشه سرو می‌شود؛ فایل‌ها باید مسیر نسبی داشته باشند (`./`).
- `gh` احراز هویت‌شده است؛ Pages روی `main` ریشه سرو می‌شود.
- **پوش مستقیم به `main` مسدود است.** جریان درست:
  `git checkout -b feat/...` → `git push -u origin feat/...` → `gh pr create` → `gh pr merge --merge --delete-branch`.

## ۸. قدم بعدی مشخص

اتصال دیگر نیاز به تغییر کد ندارد:

1. در اپ روی **☁️** بزن.
2. `Project URL` و `anon key` را از **Project Settings → API** کپی کن.
3. **تست اتصال** → اگر گفت «جدول نیست»، `supabase/schema.sql` را در SQL Editor اجرا کن.
4. **ذخیره و همگام‌سازی** → نشانگر بالای صفحه باید «ابر ✓» شود.
5. تست پذیرش: ثبت‌نام → تغییر یک چک‌باکس → بررسی رکورد در جدول `user_state`.

اگر همه سبز شد، قدم بعدی: **ایجنت Coach** (پیشنهاد اقدام بعدی بر اساس وضعیت مراحل).
